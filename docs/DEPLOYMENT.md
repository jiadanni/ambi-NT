## Prerequisites

### Hardware Requirements

**Minimum:**
- CPU: 4 cores
- RAM: 8GB
- Storage: 20GB free

**Recommended:**
- CPU: 8+ cores
- RAM: 16GB+
- Storage: 50GB+ SSD

### Software Requirements

- **OS**: Linux (Ubuntu 22.04+), macOS, or Windows with WSL2
- **Docker**: 20.10+
- **Docker Compose**: 2.0+
- **Python**: 3.11+ (for manual installation)

### Network Requirements

- Port 8000 (Node API) - can be customized
- Port 8080 (Web Client) - can be customized
- Stable internet connection
- (Optional) Tailscale for easy peer-to-peer networking

## Quick Start (Docker)

This is the **recommended** approach for Phase 1.

### 1. Clone the Repository

```bash
git clone https://github.com/yourusername/ambient-intelligence.git
cd ambient-intelligence
```

### 2. Run Setup Script

```bash
./scripts/docker-setup.sh
```

This script will:
- ✅ Check Docker and Docker Compose installation
- ✅ Generate cryptographic keys
- ✅ Create `.env` configuration file
- ✅ Build Docker images
- ✅ Start all services
- ✅ Verify everything is running

### 3. Access Your Node

- **Web Client**: http://localhost:8080
- **Node API**: http://localhost:8000
- **Health Check**: http://localhost:8000/health

### 4. Share with Friends

See [Networking Options](#networking-options) for how to make your node accessible to others.

## Manual Installation

If you prefer not to use Docker:

### 1. Install Ollama

```bash
# Linux/macOS
curl -fsSL https://ollama.com/install.sh | sh

# Verify installation
ollama --version
```

### 2. Pull AI Model

```bash
ollama pull llama3:8b
```

This downloads ~4.7GB. For other models:
```bash
ollama list  # See available models
ollama pull codellama:13b  # Example: Code-focused model
```

### 3. Clone Repository

```bash
git clone https://github.com/yourusername/ambient-intelligence.git
cd ambient-intelligence
```

### 4. Set Up Node

```bash
cd node
pip install -r requirements.txt

# Generate keys
python crypto.py

# Copy output to .env file
cd ..
cp .env.example .env
# Edit .env and paste the generated keys
```

### 5. Start Ollama

```bash
ollama serve
```

Leave this running in a terminal.

### 6. Start Node (new terminal)

```bash
cd node
python server.py
```

### 7. Serve Web Client (new terminal)

```bash
cd client-web
python -m http.server 8080
```

Or use any static file server.

## Configuration

### Environment Variables

Edit `.env` to customize:

```bash
# Node Configuration
NODE_ID=<auto-generated>          # Unique node identifier
NODE_PORT=8000                     # API port
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=llama3:8b            # Model to use
MAX_CONCURRENT_JOBS=1             # Concurrent requests (increase with more RAM)
JOB_TIMEOUT_SECONDS=120           # Job timeout
ENABLE_DEBUG_LOGS=false           # Enable for troubleshooting

# Encryption (NEVER SHARE THESE)
NODE_PRIVATE_KEY=<generated>      # Your private key
NODE_PUBLIC_KEY=<generated>       # Your public key

# Phase 2+ Only
COORDINATOR_URL=                  # Leave empty for Phase 1
HEARTBEAT_INTERVAL_SECONDS=60
```

### Choosing a Model

Available models (as of 2025):

| Model | Size | RAM Required | Use Case |
|-------|------|--------------|----------|
| llama3:8b | 4.7GB | 8GB | General purpose (recommended) |
| llama3:13b | 7.4GB | 16GB | Better quality |
| llama3:70b | 39GB | 64GB+ | Highest quality |
| codellama:13b | 7.4GB | 16GB | Code generation |
| mistral:7b | 4.1GB | 8GB | Fast, efficient |

List all available:
```bash
ollama list
```

Pull a different model:
```bash
ollama pull mistral:7b
```

Update `.env`:
```bash
OLLAMA_MODEL=mistral:7b
```

Restart services:
```bash
docker-compose restart
# Or restart manually
```

## Networking Options

### Option 1: Tailscale (Recommended for Phase 1)

**Pros:**
- Zero configuration
- Works through NAT/firewalls
- Encrypted by default
- Easy to share with friends

**Steps:**
1. Install Tailscale (see [TAILSCALE.md](TAILSCALE.md))
2. Get your Tailscale IP: `tailscale ip -4`
3. Share with friends: `http://<tailscale-ip>:8000`

**Full guide**: [docs/TAILSCALE.md](TAILSCALE.md)

### Option 2: Port Forwarding

**Pros:**
- No third-party service
- Direct connections

**Cons:**
- Complex setup
- Security risks
- Doesn't work on all networks

**Steps:**
1. Find your router's admin interface (usually 192.168.1.1)
2. Forward port 8000 to your machine's local IP
3. Get your public IP: `curl ifconfig.me`
4. Share with friends: `http://<public-ip>:8000`

**Security:** Only recommended if you understand firewall rules and DDoS protection.

### Option 3: Cloudflare Tunnel

**Pros:**
- Free
- DDoS protection
- HTTPS included

**Cons:**
- More complex setup
- Requires Cloudflare account

**Steps:**
```bash
# Install cloudflared
# Ubuntu/Debian
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared-linux-amd64.deb

# Authenticate
cloudflared tunnel login

# Create tunnel
cloudflared tunnel create ambient-node

# Route traffic
cloudflared tunnel route dns ambient-node ambient.yourdomain.com

# Run tunnel
cloudflared tunnel --config ~/.cloudflared/config.yml run ambient-node
```

### Option 4: Local Network Only

For testing with friends on the same WiFi:

1. Find your local IP:
   ```bash
   # Linux
   ip addr show | grep "inet 192"

   # macOS
   ipconfig getifaddr en0

   # Windows
   ipconfig
   ```

2. Share: `http://<local-ip>:8000`

## Troubleshooting

### Node Won't Start

**Check Docker:**
```bash
docker-compose ps
docker-compose logs node
```

**Common issues:**
- Port 8000 already in use: Change `NODE_PORT` in `.env`
- Out of memory: Reduce `MAX_CONCURRENT_JOBS` or use smaller model
- Ollama not starting: Check logs for model download issues

### Ollama Issues

**Model not found:**
```bash
# Enter container
docker exec -it ambient-node bash

# Pull model manually
ollama pull llama3:8b

# Verify
ollama list
```

**Out of memory:**
```bash
# Use smaller model
OLLAMA_MODEL=mistral:7b

# Restart
docker-compose restart
```

### Web Client Can't Connect

**CORS issues:**
- Check browser console
- Ensure node URL is correct
- Try without `https://` (use `http://`)

**Node unreachable:**
```bash
# Test from server
curl http://localhost:8000/health

# Test from client machine
curl http://<node-ip>:8000/health
```

### Slow Responses

**Increase timeout:**
```bash
# In .env
JOB_TIMEOUT_SECONDS=300

# Restart
docker-compose restart
```

**Use faster model:**
```bash
OLLAMA_MODEL=mistral:7b  # Smaller, faster
```

**Add more resources:**
```yaml
# docker-compose.yml
deploy:
  resources:
    limits:
      cpus: '8.0'
      memory: 16G
```

### Encryption Errors

**Key mismatch:**
- Regenerate keys: `python node/crypto.py`
- Update `.env` with new keys
- Restart services

**Decryption failed:**
- Check client/node using same NaCl version
- Clear browser cache and reload
- Verify public key matches

## Maintenance

### Update Software

```bash
# Pull latest code
git pull

# Rebuild
docker-compose build

# Restart
docker-compose down
docker-compose up -d

# Or use update script
./scripts/update.sh  # Coming in Phase 2
```

### Update Model

```bash
# Enter container
docker exec -it ambient-node bash

# Pull new model
ollama pull llama3:13b

# Update .env
# OLLAMA_MODEL=llama3:13b

# Restart
docker-compose restart
```

### Backup

**What to backup:**
- `.env` file (contains private keys!)
- Custom configuration
- (Optional) Ollama models (in `ollama_data` volume)

```bash
# Backup .env
cp .env .env.backup

# Backup Docker volumes
docker run --rm -v ollama_data:/data -v $(pwd):/backup \
  ubuntu tar czf /backup/ollama_backup.tar.gz /data
```

### Clean Up

```bash
# Remove old containers
docker system prune

# Remove old images
docker image prune

# Remove all data (CAUTION)
docker-compose down -v
```

## Performance Tuning

### Concurrent Jobs

```bash
# For 16GB RAM:
MAX_CONCURRENT_JOBS=2

# For 32GB RAM:
MAX_CONCURRENT_JOBS=4
```

### CPU Allocation

```yaml
# docker-compose.yml
deploy:
  resources:
    limits:
      cpus: '8.0'  # Use all 8 cores
```

### Model Selection

Balance size vs. quality:
- More RAM = larger model = better quality
- Less RAM = smaller model = faster responses

## Security Best Practices

1. **Never share `.env` file** - Contains your private key
2. **Use Tailscale or VPN** - Don't expose directly to internet
3. **Keep software updated** - Regular updates for security patches
4. **Monitor access logs** - Check for unusual activity
5. **Rate limiting** - Will be added in Phase 2
6. **HTTPS** - Will be added in Phase 2
